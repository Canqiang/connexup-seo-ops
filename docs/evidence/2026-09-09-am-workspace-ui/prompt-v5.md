把本项目的 index.html（AM 工作台原型 v4）改成**可交互的单文件原型**：不增加新页面，让 George 的一条完整验收路径真正可点击、对象正确、返回保留上下文，并修正业务口径与示例数据矛盾。保留现有配色、卡片、戳记、按钮与布局。仍然只用 seo-ops 的 tokens.css 变量，无外部依赖；允许内联 JavaScript（无框架）。

## 一、结构：单一数据源 + hash 路由

1）所有示例数据放进一个 `<script type="application/json" id="demo-data">` 里，页面所有数字、日期、状态都从它渲染，不在 HTML 里手写第二份。数据至少包含：`merchants[]`（5 家：George Merchant、Choice Brooklyn、Only Bear、可可小卤、test；每家有自己的 id、门店、负责 AM、当前 Plan、待处理事项数、风险；只有 George 数据完整，其他商户用各自的真实少量数据或「未接入」状态，绝不共用 George 的页面内容）、`inbox[]`（首页事项，每条有商户 id、类型、截止、主操作与目标路由）、`plans[]`、`tasks[]`、`workOrders[]`、`audits[]`（George 8 次：含 #28 完整、#27 专项、#26 完整、#25 失败、#24、#23、#22 专项、#21 基线；每次有 dimensions、issues（含 check_id、severity、evidence、linked_task）、coverage、rule_version）、`performance`（George 2020 Broadway 从 2026-07-01 到 2026-09-08 的逐日 8 个 GBP 指标；08-12 至 08-14 三天在「历史缺失记录」里标记为曾缺失并于 09-03 补齐，当前数据完整）、`scans[]`（Local Falcon 4 次扫描，每次 ARP、ATRP、SoLV，且 **ATRP ≥ ARP**）、`reports[]`（8 月月报 v1 已交付、第 37 周周报待审阅、自定义草稿）、`team`、`memory`、`models`。

2）用 `location.hash` 做路由，一条路由渲染一个视图，浏览器前进 / 后退 / 刷新 / 复制链接都可用：
```
#/                                    工作台
#/merchants?q=&status=                商户列表（搜索与筛选进 hash）
#/merchants/:id                       商户概览（每家商户各自的数据）
#/merchants/:id/plans                 计划与任务（含 Plan 卡）
#/merchants/:id/performance?from=&to=&cmp=&granularity=   Performance
#/merchants/:id/audit                 Audit 中心（状态、历史、周期）
#/audits/:runId                       单次诊断详情（主入口）
#/audits/:runId/compare/:otherId      对比（辅助）
#/merchants/:id/profile               资料与记忆
#/merchants/:id/reports               报告列表
#/reports/:id/v/:n                    查看指定版本（冻结）
#/reports/:id/v/:n/review             人工审阅
#/work-orders/:id?step=&version=      GBP 内容工作单
#/tasks/:id                           Task 详情（人工）
#/plans/:id                           Plan 详情
#/team  #/team/models  #/exceptions
```
每个视图渲染时更新左侧导航高亮与面包屑；「← 返回商户列表」恢复列表的搜索、筛选与滚动位置（列表状态存在 hash 里，滚动位置存 sessionStorage）。所有按钮仍带 `data-target`（现在等于真实 hash 路由）、`data-effect`、`title`。

## 二、必须走通的 George 验收路径（每一步都要能点）

1. `#/merchants` → 点「George Merchant」→ `#/merchants/george`（概览四张摘要卡，每张「查看 →」指向对应 tab）。其他 4 家商户点进去是各自的概览（Choice Brooklyn 显示两家门店与 Local Falcon 历史、Only Bear 显示「上次发布结果未知」、可可小卤显示 GSC 过期、test 显示「未接入」）。
2. 「Audit」tab → `#/merchants/george/audit`：历史表每行「查看」→ `#/audits/<那一行的 id>`（#27 的查看必须打开 #27，不是对比页）；「对比」→ 打开一个选择框（与上一次 / 首次基线 / 指定一次）→ `#/audits/28/compare/26`。
3. `#/audits/28`：单次详情页（新视图）：结论摘要、覆盖度（按检查项区分「授权数据缺失 · GSC 相关 2 项 N/A」与「公开网站检查已进行 · 官网技术 3 项」，不再写「GSC 未授权跳过官网技术」）、7 个维度得分、问题列表（每条：check_id、优先级、观察、证据引用可展开、关联 Task 可点击）、操作「交给 Orchestrator 提计划」「对比 ▾」。失败的 #25 详情页显示失败原因与「最近有效结果是 #24」，无得分。专项 #27 显示复查项，不显示总分。
4. `#/audits/28/compare/26`：沿用 v4 对比页；换成与 #21 比较时提示「评分规则 v1 → v2，不可直接比较」并只并列。
5. 「Performance」tab → `#/merchants/george/performance`：默认期间「最近 28 天」，日期菜单**默认收起**；首屏直接是期间、四张指标卡、趋势。点统计期间 → 展开面板 → 选「自定义 08-01 至 08-31」→ 点「应用筛选」→ **真的重算**四张指标卡、比较期、趋势 SVG、逐日表和数据质量表（从 demo-data 逐日数据聚合），hash 变成 `?from=2026-08-01&to=2026-08-31&cmp=prev_equal&granularity=day`。点某个关键词 → `#/keywords/brunch?from=…&to=…` → 「← 返回」回到同一期间的 Performance。粒度切换日 / 周 / 月只改展示，不改期间。数据质量表区分「当前状态：完整」与「历史缺失记录：08-12 至 08-14 曾缺失，09-03 已补齐」，最后成功同步显示 09-08。
6. 「生成报告」→ 带入当前筛选的配置弹窗 → 确认 → 在 `reports[]` 里新增一条「自定义 08-01 至 08-31 · 草稿 · 未审核 · v1」（内存状态，刷新后丢失可以，但要提示「演示：刷新后重置」）→ 自动跳到 `#/reports/<新 id>/v/1`：显示冻结的数字（生成时刻的聚合结果与 data manifest hash）。
7. 「审阅」→ `#/reports/<id>/v/1/review`：完整报告 + 质量提示 + 「审核通过」「退回」；通过后状态变「已审核」，主操作变「查看报告」，旁边「下载」「交付记录」。
8. 「下载」→ 用 `<a download>` 下载冻结的自包含 HTML（内容 = 生成时冻结的数字，不读当前数据）。
9. 在 Performance 页加一个演示按钮「模拟补数：把 08-20 曝光 +120」→ 当前 Performance 数字变化，并出现「数据已于今天补齐 / 修正」；回到刚才的报告 → 数字不变，列表行出现「有更新的来源数据」标记与「生成修订版」按钮；点它 → 新增 v2、v1 仍可查看。

## 四、必须修正的口径与数据矛盾
