修改本项目已有的 index.html（AM 工作台界面原型），保留视觉骨架（配色、侧栏、卡片、戳记、按钮），按下面的审阅意见改业务交互，并新增 3 个区块。仍然是静态原型集，桌面 1280px 起，只用 seo-ops 的 tokens.css 变量，无外部依赖。改完后 9 个区块的 `<section id>` 依次为：am-home、am-merchant-space、am-gbp-work-order、am-task-detail-human、am-dispatch-drawer、am-team、am-memory、am-model-cost、am-reports。

## 一、修正四处流程

1）对话派单（am-dispatch-drawer）：Orchestrator 的回复改成两部分。上半部分标题「已在 Plan #12 授权范围内创建并分派」，两张卡直接带「已派单」戳记：「GBP 帖子草稿 · 内容 Agent」「确认 Weekday Brunch Set 价格 · xander」，不再有「应用提案」按钮。下半部分标题「超出授权范围 · 需要你整体批准」，一组两张关联卡：「新增 Local Falcon 扫描 · 40 credits」「扫描后重算关键词监测集」，组底部只有一个主按钮「整体批准这 2 项」和次按钮「退回」，说明文字「关联任务整体批准，避免只创建前半段」。系统灰字行：「范围内 2 项已派单 · 范围外 2 项等你批准」。

2）审核是独立的人工任务：把原来的 am-task-detail 换成 am-gbp-work-order，标题「GBP 内容工作单 · brunch 主题 · George Merchant」。主区是一条竖向流水线，四步各自独立显示负责人、状态、交付物：
   ① 草稿 · 内容 Agent · 已完成 09-09 10:12 · 交付物：帖子 v2（正文 + 图片 + CTA）
   ② 审核 · xander（分派给你）· 进行中 · 交付物：批准或退回记录
   ③ 发布 · 发布 Agent · 待前置（等第 ② 步）
   ④ 远端核验 · 系统 · 待前置（等第 ③ 步）
   第 ② 步展开为完整审核视图：完整正文（不截断）；真实图片区（用占位块但标注「商户照片 · 来源：FBR 菜品图 #17 · 已授权」，不再写「待商户提供实拍」）；CTA「了解更多 → https://georgemerchant.example/menu」（显示真实目标网址）；目标门店「2020 Broadway · New York」；版本「帖子 v2 · checksum b4de70ec…」；一行依赖说明「本版不含价格。价格确认任务 T-1205 已解除对本版的阻塞；含价格的更新帖会另建工作单」。操作：主按钮「批准这一版」（危险色，弹确认对话框：「批准后发布 Agent 会把帖子 v2 写入 Google 门店 2020 Broadway。发布后只能删除，不能退回草稿。确认？」）和次按钮「退回并说明」。第 ③ ④ 步折叠显示。

3）首页「需要我决定」的 GBP 卡：主按钮改为「审阅草稿」，不再出现「批准并发布」；卡上只保留结论一句、影响一句、操作，依据放在「展开依据 ›」折叠里。产物预览保留前 80 字但标注「完整内容在审阅页」。

4）人工任务（am-task-detail-human）：去掉「标记为无法完成」，改成四个次操作：「暂时受阻」「请求协助」「转交给…」「取消任务」；取消需要填原因并弹确认对话框；说明行「受阻和协助请求会交给 Orchestrator 接续处理，不会关闭任务」。
