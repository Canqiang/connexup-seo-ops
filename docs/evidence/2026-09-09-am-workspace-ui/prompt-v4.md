## 六、交互契约（这一版必须补，不只补页面）

按 `docs/superpowers/specs/2026-09-09-am-os-interaction-contract-design.md` 执行：

1）**每个按钮和链接**都加两个属性：`data-target`（真实路由或本页锚点，如 `/work-orders/WO-1204?step=review&version=2`、`#am-audit-center`）和 `data-effect`（`open` 打开对象 / `submit` 改变状态 / `expand` 就地展开 / `external` 新标签打开 / `none`）。用 `title` 属性显示「→ 目标 · 打开方式 · 是否改变状态」，例如 `title="→ 工作单 WO-1204 第②步 v2 · 当前页打开 · 不改变状态"`。

2）**修正页内锚点**，让静态原型的跳转指向正确对象：
   - 左侧导航「商户」→ 新增的轻量区块 `am-merchant-list`（放在 am-home 之后）：搜索框、状态筛选、5 家商户的表（名称、门店数、负责 AM、当前 Plan、待你处理、风险），每行名称链接到 `#am-merchant-space`；顶部一行「返回时恢复搜索、筛选、分页与滚动位置」。
   - 左侧导航「任务与计划」→ 新增的轻量区块 `am-task-list`（放在 am-merchant-list 之后）：筛选条（商户 / Plan / 执行者 / 状态）、8 行任务表（含工作单归属列），每行链接到对应区块（`#am-gbp-work-order` 或 `#am-task-detail-human`）；「查看 Plan」按钮指向本区块内的一张「Plan #12」详情卡（目标、允许 / 不允许、预算与已用、7 项任务、批准记录 2 条）。
   - 左侧导航「数据与报告」→ `#am-reports`；商户空间 tab「Performance」→ `#am-performance`、「Audit」→ `#am-audit-center`、「报告」→ `#am-reports`、「资料与记忆」→ `#am-memory`、「计划与任务」→ `#am-task-list`。

   - 团队页成员名、Skill 名可点击（`data-effect="open"`，目标 `/team/members/:id`、`/team/skills/:id`），但本页不新增区块。

3）**六种状态样例面板**：在 am-gbp-work-order 第 ② 步下方加一张横向面板「『批准这一版』的六种情况」，六个小卡并排：正常（「已保存批准 #A-91 · 发布 Task 已入队」，不写「发布成功」）、处理中（按钮 busy 态「正在校验…」，说明「按钮已锁定，可离开后从工作单回来查看」）、失败（Notice error「服务端拒绝：批准有效期字段缺失」，表单值保留，按钮「重试」）、结果未知（「请求超时，正在读回批准状态…」，说明「不会自动重新提交」）、状态过期（ConflictBanner「内容已变化：帖子 v3 已替换 v2，请重新审阅」，按钮「重新载入」，说明「服务端按 checksum 校验，不只靠按钮置灰」）、返回 / 关闭（「关闭后回到工作台『需要我决定』第 1 项，焦点回到『审阅草稿』按钮」）。
