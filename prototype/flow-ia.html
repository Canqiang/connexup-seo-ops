8 处图例（金色圆点对应画面位置）

1
首页 = 异常清单，不是流水线

按“需要动的原因”分组，卡得最久的置顶、标天数；首屏一秒回答“三十家今天该动哪家”。常驻全量流水线被 Council 判为视觉撒谎。

2
等待商家是一等公民

问卷在系统外由商家填——“第 5 天未回 + 重发”是首页最重要的状态。这是互评轮抓出的第二用户面盲点。

3
＋ 新店是唯一新建入口

店名/官网 → 生成定制问卷 → 外链发放。新店从这里自然进入同一条生命周期。

4
阶段轨 = 商户的属性

问卷→关键词→双审计→排名基线→Plan→执行→核验；未到段置灰、当前段高亮。界面上没有 agent 词汇，按钮叫“确认 Plan”。

5
下一步只有一个

当前阶段卡 = 最新产物摘要 + 单个主按钮，背后才映射到既有五种 SOP。点“确认 Plan”试试，任务会真的生成。

6
任务/证据原样下沉

现有任务系统、证据脊柱、审批门嵌入商户页下一层，一行不改——红线可见性不降级。

7
执行 = 人工工单

EXECUTE 关闭期，审批授权后由人工按工单执行、逐条“完成并回填证据”走既有待核验流。这是操作员当下的主职。

8
老店 = 同一块屏的稳态

同一条轨 + 轮次徽标 + 与上期对比（只放数字，不做图表）。没有“新店变老店”的身份切换，阶段可回退重跑。

落地顺序（Council 裁决）：① merchant.stage 字段 + 生命周期页（纯读 + 按钮触发现有 SOP）→ ② 首页切异常清单 → ③ 问卷 MVP（生成 → 外链发放 → sent/filled/overdue + 重发）→ ④ Plan 渲染成清单、逐条“转任务”（复用现有建任务）→ ⑤ 人工执行工单 + 证据回填闭环 → ⑥ ranking 快照表（local/organic/词/位次/日期，不做图表）→ ⑦ 老店轮次套同一骨架。①②④⑤几乎零后端；红线（审批只记录授权、EXECUTE 关闭）全程不动。
第一件事：拿这两屏给真实操作员走查，只问一句：“这三十家今天该动哪家？下一步点哪里？”——30 秒答得出来再动代码。
